Why is it called a "Cost"?
Imagine you run a business:

Wrong predictions cost you money.
If you predict a house price is $100,000 but it's actually $150,000, you lost $50,000.
The "cost" is how much money you lost because of your bad guesses.
The cost function measures this "financial penalty" for being wrong. The higher the cost, the worse your model.


Why is it called a "Loss"?
Same idea, just different wording:

Every time you make a wrong prediction, you lose accuracy.
The loss function calculates exactly how much accuracy you lost.

Why does Gradient Descent minimize the cost/loss?
 
Question
Answer
What does Gradient Descent do?
It tries to minimize the cost/loss function.
How does it know it's improving?
When the cost/loss goes down, the model is getting better.
When is it done?
When the cost/loss stops decreasing (reaches a minimum).

In your code:
python
def compute_mse_loss(X, y, weights):
# This is your COST function
predictions = X @ weights
return (1/len(y)) * np.sum((predictions - y) ** 2)

# In your training loop:
loss_history.append(compute_mse_loss(...)) # Recording the cost/loss at each step

# When you plot loss_history, you're watching the cost DECREASE over time
plt.plot(loss_history)
plt.ylabel('Cost/Loss (MSE)')

MSE, Cost Function, and Loss Function are three interchangeable names for the exact same thing: a number that measures how wrong your model is, which Gradient Descent works tirelessly to minimize!

Transform XX → To fix the shape of the line.
Transform yy → To fix the variance of the errors.

When you train on log(y_train), your model predicts log(y).

HuberRegressor is just a type of math (loss function). It does not transform your data.
You just give it X and y, and it predicts y directly.
No np.exp(), no reversal. You only use np.exp() if you specifically took np.log(y) before feeding it to Huber.
python
# If you did NOT take log(y):
model = HuberRegressor()
model.fit(X_train, y_train) # Predicts dollars directly
y_pred = model.predict(X_test) # Output is already in dollars. NO REVERSAL needed.

# If you DID take log(y) AND used Huber:
y_train_log = np.log(y_train)
model.fit(X_train, y_train_log)
y_pred_log = model.predict(X_test)
y_pred = np.exp(y_pred_log) # YES, you must reverse it because you took log(y)!

2. What do we use for X^2, X^3 (Polynomials)?
Answer: NOTHING. You DO NOT reverse them.

When you add X^2, you are just creating a new feature (like giving the model a second clue).
The model predicts y directly from these new features.
The prediction is already in the original units (dollars).
python
# You add X^2 as a new column:
X_train_new = np.column_stack([X_train, X_train**2])
model.fit(X_train_new, y_train)

# When you predict, you just give the model the new features:
X_test_new = np.column_stack([X_test, X_test**2])
y_pred = model.predict(X_test_new) # Output is already dollars. NO REVERSAL!
